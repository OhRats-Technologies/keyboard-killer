Keyboard-Killer documentation

Install. Set up. Look and speak.

Everything a new user needs for the Linux release, and an honest list of what is not ready.

01 / Install

One command

On Debian or Ubuntu, the installer uses the self-contained .deb and apt. On other Linux distributions it installs the AppImage for the current user.

curl -fsSL https://keyboard-killer.ohrats.party/install.sh | sh

Both paths verify the published SHA256SUMS; the binaries are hosted on GitHub and mirrored on this site. The .deb includes the /dev/uinput udev rule, a desktop entry, and an optional systemd user unit.

02 / Requirements

Linux, x86_64, two cameras

  • Linux x86_64, PipeWire or PulseAudio, and a writable /dev/uinput.
  • Two stable V4L2 cameras for stereo gaze. The app reports a single camera as degraded; a single-camera mode is not implemented.
  • CPU-only speech recognition by default (Parakeet int8). CUDA is opt-in; no CUDA toolkit is required for the default install.
  • Screen capture and AT-SPI are optional; pointer/voice commands work without an AI provider.
03 / First run

Guided setup, resumable

  1. Permissions: camera, microphone, input devices, screen capture.
  2. Cameras: choose two stable /dev/v4l/by-id devices.
  3. Calibration: the full-screen target window. Calibration is required before vision starts.
  4. Speech: download the pinned Parakeet model (about 630 MB); it is the only speech engine.
  5. Optional AI provider, practice, and ready.

Setup progress is stored in onboarding.json; closing the app does not restart the flow.

04 / CLI

The terminal stays a fallback

keyboard-killer doctor
keyboard-killer doctor --json
keyboard-killer models status
keyboard-killer providers status
keyboard-killer run-voice --seconds 5 --dry-run
05 / Privacy

Local by default

Camera, speech, and history stay on the machine. API keys live in the OS keychain. Screenshots only leave the device if you explicitly enable a remote gaze VLM; text providers receive the transcribed command and a trimmed page/UI summary.

06 / Known limitations

What is not ready

  • macOS and Windows are capability stubs; no installers are published. Linux is the only implemented host.
  • Two-camera calibration, /dev/uinput injection, screen capture, and GNOME Wayland capture are hardware checks; they are not claimed as tested on every desktop.
  • A persistent click-through overlay is available on X11. On Wayland the app uses the tray/toast and Firefox HUD fallback.
  • The Firefox extension and a targeting benchmark are not packaged yet.
